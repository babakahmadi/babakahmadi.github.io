Consistent hashing

30 January 2022·674 words·4 mins·
Author
Babak Ahmadi

In computer science, there are a lot of different data structures with a variety of use cases. Hash Table (Hash Map) is one of these data structures and whether we know it or not, we use it every day when we work with our computer. hash tables are used in different kinds of areas such as pattern matching, password verification, file system, message digest, compilers and, a lot of other things. Hashing is a technique or process of mapping any kind of object into the hash table by using a hash function. It is done for faster access to elements. The efficiency of mapping depends on the efficiency of the hash function used. A hash function is a function that gets an object as input and returns an integer value (in most cases, it can return any kind of long number or string). With this number as an index, we can put that object in that address of the hash map and whenever we want to check if that object has already existed, we can apply the function on that object and check whether there is in that place or not.

Sometimes, two different objects have the same hash value and we need to put both in the same place. When this happens, we call it collision and, because we cannot put two of them in one place, we need to use some methods to fix it. There are a lot of solutions to resolve this issue (but we’re not going to explain it in this blog)

As it is obvious, one of the most important problems with hash is the size of the hash table. Hash functions can return very big numbers and because of that, we need to create a very large hash map to manage it. So to fix this problem, we use a modulo to shrink that huge space.

Until now, we have thought that we have a lot of space in our system ram and we can use that for our applications, but it would be not true in some cases especially when we want to handle a lot of requests in a large scale environment. In this situation, one of the most common solutions is to use different systems altogether to share the load between them. To do that we have to find a solution to know how to select the specific node for each request or data and the common way to do that is using the hash function and modulo by the number of nodes.

Great. Everything goes right. (You know, from here it’s not important how each of the nodes handle that data because we have spoken about it already. From here, we just speak about the nodes and how to handle their issue and we assume that each node can handle its task perfectly) In distributed systems, it is very natural to add new nodes or to remove some of them. it is very normal for nodes to fail at any time. Suppose we add a new Object, one specific node is selected then that node takes care of it. Now, we missed one of our nodes, and we need to move that object to another node because we need that to use for some search.

what the hell? we need to move all of the objects from the nodes to another node because the number of nodes is changed and our policy is changed because of that. This is very expensive and everyone tries to prevent doing this kind of thing. we always try to do it in a way that if one of the nodes fails or a new node adds to the cluster, we don’t need to move a lot of data from one node to another. So, the most important objective for us is to minimize the size of movements. It means, we need to change our policy to select the node in a way if any node fails or any node adds, we move the least data we can.
